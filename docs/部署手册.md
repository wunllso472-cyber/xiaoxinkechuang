## 1. 部署规划

### 1.1 部署组成

| 组件 | 部署位置 | 数量 | 说明 |
|---|---|---|---|
| 服务端 `xiaoxin` | CentOS 服务器 | 1 | FastAPI 单进程服务，同时提供接口、管理端、运维 H5 |
| 数据库 | 同一台服务器，或独立数据库服务器 | 1 | PostgreSQL 10+，或人大金仓 KingbaseES V8R6（见 [2.8](#28-使用人大金仓kingbasees)）；存放业务数据和知识库向量 |
| 桌面客户端 | 每台终端 | N | .deb（麒麟 / 统信 / Ubuntu）或 exe（Windows） |
| 大模型 | 公网 API 或内网私有化 | 可选 | DeepSeek / 通义千问 / 星辰 TeleChat 等；未配置时问答由“本地兜底”返回提示 |

### 1.2 服务器环境要求

| 项目 | 最低 | 推荐 |
|---|---|---|
| CPU | 4 核（鲲鹏 / 飞腾 / 海光 / 兆芯均可） | 8 核及以上 |
| 内存 | 8 GB | 16 GB 及以上（知识库较大时更多） |
| 磁盘 | 100 GB | 200 GB 以上 SSD；上传文件和知识库文档都存在本地 |
| 操作系统 | CentOS 7.9 | CentOS Stream 8 / 9；麒麟服务器版 V10、openEuler 等 RHEL 系可参照执行 |
| Python | 3.8 及以上 | 3.9 / 3.11 |
| PostgreSQL | 10 及以上 | 13 及以上 |
| 人大金仓（代替 PostgreSQL 时） | KingbaseES V8R6 | 由 DBA 提供已建好的库和用户，本手册不涉及金仓的安装 |
| 权限 | 普通用户（按 [3.5](#35-无-root-权限部署普通用户目录) 部署） | root 或 sudo（可使用一键脚本、systemd） |

各版本 CentOS 的默认软件版本和处理方式（一键部署脚本会自动按下表处理）：

| 系统 | 自带 Python | 自带 PostgreSQL | 脚本处理方式 |
|---|---|---|---|
| CentOS 7 | 3.6（过旧） | 9.2（过旧） | Python 通过 SCL 安装 rh-python38；PostgreSQL 从官方源安装 13 |
| CentOS 8 / Stream 8 | 3.6，可装 python39 | 10（模块流可选 12 / 13） | 安装 python39；PostgreSQL 切换到 13 模块流后安装 |
| CentOS Stream 9 | 3.9 | 13 | 直接使用系统自带版本 |

> **CentOS 7（2024-06 停止维护）和 CentOS 8（2021-12 停止维护）的官方 yum 源已下线**，安装前必须把 yum 源改为单位内部源或归档源（vault），否则 `yum install` 会失败，见 [9.2](#92-centos-yum-源不可用)。

### 1.3 网络与端口

| 端口 | 方向 | 用途 |
|---|---|---|
| 8000/TCP | 终端、管理员浏览器、运维手机 → 服务器 | 服务端接口、管理端、H5（可通过 `PORT` 修改） |
| 5432/TCP | 仅服务器本机（或仅服务端 → 独立数据库服务器） | PostgreSQL，不要对终端网段开放 |
| 54321/TCP | 同上 | 人大金仓默认端口（使用金仓时），不要对终端网段开放 |
| 443/TCP | 服务器 → 公网 | 仅在使用 DeepSeek 等公网大模型时需要 |

### 1.5 部署流程总览

```
准备服务器（配置 yum 源）→ 安装 PostgreSQL → 创建数据库和用户
→ 部署服务端程序 → 初始化数据库（建表 + 初始数据）→ 启动服务（首次启动导入示例知识库）
→ 运行验证脚本 → 管理端修改默认密码、配置大模型与接入密钥 → 打包并安装客户端 → 验证终端接入
```

使用 [3.1 一键部署脚本](#31-一键部署推荐) 时，上述服务端步骤全部自动完成。

两种情况下流程有变化：

- **数据库是人大金仓**：“安装 PostgreSQL → 创建数据库和用户”两步改为“向 DBA 获取金仓的地址、库名、用户，并确定一个独立的 schema 名”，见 [2.8](#28-使用人大金仓kingbasees)。
- **服务器没有 root 权限**（或系统自带 Python 过旧又不能安装系统软件包）：服务端步骤按 [3.5](#35-无-root-权限部署普通用户目录) 执行，用启停脚本和 crontab 代替 systemd。

## 2. 数据库安装与初始化

> 使用一键部署脚本且数据库与服务端同机时，本章 2.1 ~ 2.4 由脚本自动完成，可直接跳到 [2.5](#25-初始化表结构和初始数据) 了解初始化内容。以下情况需要按本章手动执行：手动部署、数据库由 DBA 统一管理、使用独立数据库服务器。
>
> **数据库使用人大金仓时，2.1 ~ 2.4、2.5 方式 B、2.7 不适用**，请直接按 [2.8](#28-使用人大金仓kingbasees) 执行；2.5 中关于初始数据内容和初始化工具用法的说明仍然适用。

### 2.1 安装 PostgreSQL

**方式一：PostgreSQL 官方源（推荐，各 CentOS 版本通用，可选择版本）**

```bash
EL=$(rpm -E %{rhel}); ARCH=$(uname -m)
sudo yum install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-$EL-$ARCH/pgdg-redhat-repo-latest.noarch.rpm
# CentOS 8 / Stream 8 / Stream 9 需先禁用系统自带的 postgresql 模块
[ "$EL" -ge 8 ] && sudo dnf -qy module disable postgresql
sudo yum install -y postgresql13-server postgresql13-contrib

# 初始化数据目录（UTF8 编码）
sudo PGSETUP_INITDB_OPTIONS="--encoding=UTF8 --locale=C" /usr/pgsql-13/bin/postgresql-13-setup initdb
sudo systemctl enable --now postgresql-13
```

服务名 `postgresql-13`，数据目录 `/var/lib/pgsql/13/data`，命令在 `/usr/pgsql-13/bin`。

**方式二：系统自带版本（仅 CentOS 8 / Stream 8 / Stream 9）**

```bash
sudo dnf -qy module enable postgresql:13      # 仅 CentOS 8 / Stream 8；Stream 9 自带 13，跳过此行
sudo dnf install -y postgresql-server postgresql-contrib
sudo PGSETUP_INITDB_OPTIONS="--encoding=UTF8 --locale=C" postgresql-setup --initdb
sudo systemctl enable --now postgresql
```

服务名 `postgresql`，数据目录 `/var/lib/pgsql/data`。

> **CentOS 7 不要使用自带的 9.2 版本**，必须按方式一安装。
>
> **内网离线安装**：在可联网的同版本 CentOS 上执行 `yumdownloader --resolve postgresql13-server postgresql13-contrib`（或从内部镜像获取），把下载的 rpm（`postgresql13`、`postgresql13-libs`、`postgresql13-server`、`postgresql13-contrib` 及依赖）拷贝到服务器，执行 `sudo yum localinstall -y *.rpm`。

确认版本：

```bash
psql --version          # 官方源安装：/usr/pgsql-13/bin/psql --version
```

### 2.2 配置访问认证

编辑 `pg_hba.conf`（官方源：`/var/lib/pgsql/13/data/pg_hba.conf`；系统自带：`/var/lib/pgsql/data/pg_hba.conf`），把本机 TCP 连接的认证方式改为 `md5`（PostgreSQL 14+ 也可用 `scram-sha-256`）：

```
# TYPE  DATABASE  USER  ADDRESS         METHOD
host    all       all   127.0.0.1/32    md5
host    all       all   ::1/128         md5
```

```bash
sudo systemctl restart postgresql-13      # 系统自带版本：sudo systemctl restart postgresql
```

**数据库与服务端分开部署时**，在数据库服务器上额外配置：

```bash
# postgresql.conf
listen_addresses = '*'                    # 或数据库服务器的内网 IP

# pg_hba.conf：只允许服务端 IP 连接业务库
host    xiaoxin   xiaoxin   10.0.0.10/32    md5

# 防火墙只对服务端 IP 放行 5432
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="10.0.0.10/32" port port="5432" protocol="tcp" accept'
sudo firewall-cmd --reload
sudo systemctl restart postgresql-13
```

### 2.3 创建数据库和用户

使用部署包中的 `server/deploy/sql/00_create_db.sql`（可重复执行：用户已存在时只更新密码，数据库已存在时跳过）：

```bash
cd /root/xiaoxin-server/deploy/sql
sudo -u postgres psql -v ON_ERROR_STOP=1 \
  -v db_user=xiaoxin -v db_pass='请替换为强密码' -v db_name=xiaoxin \
  < 00_create_db.sql
```

> 用 `<` 重定向而不是 `-f`：脚本在 `/root` 下，postgres 用户没有读取权限，重定向由 root 读取文件后再交给 psql。

脚本内容：创建登录用户 `xiaoxin`；以 `template0`、`UTF8` 编码创建数据库 `xiaoxin`，属主为 `xiaoxin`；收回 `PUBLIC` 对该库的权限。

> 也可以手动执行等价 SQL：
> ```sql
> CREATE USER xiaoxin WITH PASSWORD '强密码';
> CREATE DATABASE xiaoxin OWNER xiaoxin ENCODING 'UTF8' TEMPLATE template0;
> REVOKE ALL ON DATABASE xiaoxin FROM PUBLIC;
> ```
> 数据库属主必须是业务用户 `xiaoxin`。PostgreSQL 15 起普通用户默认不能在 `public` 模式中建表，只有数据库属主可以，属主不对会导致建表时报 `permission denied for schema public`。

### 2.4 验证连接

```bash
psql "postgresql://xiaoxin:密码@127.0.0.1:5432/xiaoxin" -c "select version();"
# 官方源安装且未加入 PATH 时，使用 /usr/pgsql-13/bin/psql
```

能输出版本号即表示用户、密码、`pg_hba.conf` 均配置正确。然后把连接串写入 `/opt/xiaoxin/config.yaml`（一键脚本会自动写入）：

```yaml
database:
  url: "postgresql+psycopg2://xiaoxin:密码@127.0.0.1:5432/xiaoxin"
```

> 密码中有 `@`、`:`、`/`、`#`、`%`、`&` 等特殊字符时需要做 URL 编码（如 `@` 写成 `%40`、`#` 写成 `%23`）。可以用命令生成：`python3 -c "from urllib.parse import quote; print(quote('你的密码', safe=''))"`。一键脚本会自动编码。

### 2.5 初始化表结构和初始数据

数据库共 **39 张表**（清单见《数据库设计说明书》），初始数据分为三类：

| 类别 | 内容 | 写入时机 |
|---|---|---|
| 基础数据 | 默认账号、大模型配置、系统设置、客户端采集参数、预警规则、型号数据字典、意图、合同审查规则与模板、内置工具、消息模板、云桌面服务器、评估测试集，共 13 类 103 条，明细见[附录 A](#附录-a-初始化数据清单) | 初始化时 |
| 知识库 | “信创运维知识库”（导入示例文档 `data/sample_kb.md`）、“信创政策知识库” | 初始化工具执行时，或使用 SQL 脚本时由服务首次启动写入 |
| 演示数据 | 12 台演示终端及 14 天活跃记录、5 张工单、2 条案例 | 仅当 `server.seed_demo: true`（或 `--demo`）且终端表为空时；**生产环境不要写入** |

所有初始化方式都是“**按表判断，表为空才写入**”：已有数据的表不会被修改、清空或重复写入，可以放心重复执行。

提供两种初始化方式，**任选其一**：

| 方式 | 执行者 | 适用场景 |
|---|---|---|
| A. 初始化工具 `python -m app.init_data`（推荐） | 运维人员，在服务端服务器上执行 | 一键部署（脚本自动调用）、手动部署 |
| B. SQL 脚本 `deploy/sql/01_schema.sql`、`02_init_data.sql` | DBA，用 psql 执行 | 数据库由 DBA 统一管理、需要审核建表语句、服务端服务器不允许直接建表 |

#### 方式 A：初始化工具（推荐）

前提：已按第 3 章部署程序和虚拟环境，`config.yaml` 中的 `database.url` 已正确配置。

```bash
cd /opt/xiaoxin
sudo -u xiaoxin venv/bin/python -m app.init_data
```

输出示例（末尾自动执行一次检查）：

```

==> 表结构已就绪
==> 初始数据已写入（已有数据的表自动跳过）
==> 数据库：127.0.0.1:5432/xiaoxin
    版本：PostgreSQL 13.16 on x86_64-pc-linux-gnu, compiled by gcc (GCC) ..., 64-bit
    表数量：39 / 39

    表名                     记录数
    alert_rule               9
    chat_intent              2

    kb                       2
    kb_chunk                 9
```

工具的其他用法：

| 命令 | 作用 |
|---|---|
| `python -m app.init_data` | 建表 + 基础数据 + 知识库，然后输出检查结果 |
| `python -m app.init_data --demo` | 同上，并写入演示数据（仅测试环境） |
| `python -m app.init_data --check` | 只检查：数据库连接、schema（已配置时）、版本、表数量、各表记录数、用户列表，不写入任何数据；表不全时退出码为 1 |
| `python -m app.init_data --export-sql DIR` | 按当前程序版本重新生成 PostgreSQL 脚本 `01_schema.sql`、`02_init_data.sql`（不连接正式数据库） |

> 不执行初始化工具、直接启动服务也可以：服务每次启动时都会执行相同的建表和初始数据逻辑。单独执行工具的好处是可以在启动服务前看到明确的初始化结果，连接或权限问题也会直接显示出来。

#### 方式 B：SQL 脚本（DBA 执行）

脚本位于部署包 `server/deploy/sql/`，**必须用业务用户 `xiaoxin` 执行**（以 postgres 执行会导致表属主不对，服务端无权写入）：

```bash
cd /root/xiaoxin-server/deploy/sql
export PGPASSWORD='业务用户密码'
# 1. 建表（39 张表及索引；IF NOT EXISTS，可重复执行）
psql -h 127.0.0.1 -U xiaoxin -d xiaoxin -v ON_ERROR_STOP=1 -f 01_schema.sql
# 2. 基础数据（103 条；只能在空库执行，sys_user 已有数据时报错退出且不写入任何数据）
psql -h 127.0.0.1 -U xiaoxin -d xiaoxin -v ON_ERROR_STOP=1 -f 02_init_data.sql
unset PGPASSWORD
```

说明：

- `02_init_data.sql` 不含知识库和演示数据。知识库由服务**首次启动**时自动创建，并导入 `data/sample_kb.md`（需要服务端程序做文本切分和向量化，不能用 SQL 完成）。
- 脚本中的大模型 API Key 均为空，部署后在管理端填写。
- 脚本中默认账号的密码为 PBKDF2-SHA256 加盐哈希，对应明文见附录 A.1，上线前必须修改。
- 脚本由 `python -m app.init_data --export-sql` 根据程序中的表定义生成，与当前程序版本严格对应。程序升级后如需新版脚本，在新版本目录中重新导出即可。
- 使用方式 B 时，需在首次启动服务**前**确认 `config.yaml` 中 `server.seed_demo: false`，否则服务启动时会因为终端表为空而写入演示数据。

### 2.6 验证数据库初始化

方式 A 执行完会自动输出检查结果，也可以随时执行：

```bash
cd /opt/xiaoxin && sudo -u xiaoxin venv/bin/python -m app.init_data --check
```

或使用 SQL 检查脚本（只读）：

```bash
psql -h 127.0.0.1 -U xiaoxin -d xiaoxin -f /root/xiaoxin-server/deploy/sql/03_check.sql
```

预期结果：

### 2.8 使用人大金仓（KingbaseES）

金仓兼容 PostgreSQL 协议，服务端直接用 `postgresql+psycopg2://` 连接串和 psycopg2 驱动连接，**不需要安装金仓专用驱动，也不需要修改金仓的库级参数**。已在 KingbaseES V008R006C006B0021（Oracle 兼容模式）上完成初始化、部署验证和冒烟测试（环境见 [1.6](#16-已验证的部署环境)）。

#### 与 PostgreSQL 部署的区别

| 项目 | PostgreSQL | 人大金仓 |
|---|---|---|
| 数据库安装、建库建用户 | 2.1 ~ 2.3，或由一键脚本完成 | 由 DBA 提供已有的库和用户，不使用 `00_create_db.sql` |
| 默认端口 | 5432 | 54321 |
| `database.schema` | 留空（表建在 `public`） | **必须填写**（如 `xiaoxin`），表建在独立 schema 下 |
| 初始化方式 | 方式 A 或方式 B | 只能用方式 A（初始化工具）；`01_schema.sql`、`02_init_data.sql`、`03_check.sql` 不带 schema，不适用 |
| 命令行工具 | `psql`、`pg_dump`、`pg_restore` | `ksql`、`sys_dump`、`sys_restore`（金仓安装目录下） |

`database.schema` 必须填写的原因：金仓自带系统视图 `sys_catalog.sys_user`，与本系统的用户表同名，而且解析时优先于 `public`，表不放在独立 schema 下，查询 `sys_user` 得到的是系统视图。另外金仓的库通常是多个业务共用的（实际环境的 `public` 下已有其他业务的表），独立 schema 也便于区分和清理。

#### 步骤

**1. 向 DBA 获取连接信息**：金仓地址、端口（默认 54321）、库名、用户、密码。该用户需要有在库中创建 schema 和建表的权限（实际部署使用的是 `system` 用户）。库的编码应为 UTF8。

**2. 验证连通**（在服务端服务器上，用已装好依赖的虚拟环境执行；路径按实际部署目录调整）：

```bash
cd /opt/xiaoxin        # 无 root 部署为 ~/xiaoxin
venv/bin/python -c "
import psycopg2
c = psycopg2.connect(host='金仓IP', port=54321, dbname='库名', user='用户', password='密码', connect_timeout=10)
cur = c.cursor()
for q in ('select version()', 'show server_encoding', \"select current_setting('database_mode')\"):
    cur.execute(q); print(cur.fetchone()[0])
"
```

实际环境的输出：

```

UTF8
oracle
```

**3. 写入配置**（`config.yaml`，权限保持 600）：

```yaml
database:
  url: "postgresql+psycopg2://system:密码@金仓IP:54321/库名"    # 密码中的特殊字符需 URL 编码，如 @ 写成 %40
  schema: "xiaoxin"                                             # 金仓必须填写
```

也可以不改文件，用环境变量 `XX_DATABASE_URL`、`XX_DB_SCHEMA` 传入（适合不希望密码落盘或临时初始化的场景）。地址填金仓实际监听、且其访问控制（`sys_hba.conf`）允许的地址；实际部署中金仓与服务端同机，填的是服务器的内网 IP。

**4. 初始化**（自动创建 schema、建表、写入基础数据；可重复执行）：

#### 服务端自动处理的兼容问题

以下问题由 `app/db.py` 在连接时自动处理，对普通 PostgreSQL 没有影响：

| 问题 | 不处理时的现象 | 处理方式 |
|------|------|------|
| `version()` 返回 `KingbaseES V008R006...`，SQLAlchemy 只认 `PostgreSQL x.y` 格式 | 连接即报 `Could not determine version from string` | 改用 `server_version_num`（金仓报告为 120001，即兼容 PostgreSQL 12.1）识别版本 |
| Oracle 兼容模式默认把空串存成 NULL（`ora_input_emptystr_isnull=on`） | 写入时报 `null value in column "xxx" violates not-null constraint` | 每个连接按会话设为 `off`，不修改库级参数，不影响库内其他业务 |
| Oracle 兼容模式的保留字比 PostgreSQL 多（本系统涉及字段名 `level`） | 建表报 `syntax error at or near "level"` | 连接时读取金仓的 `pg_get_keywords()`，命中保留字的字段名在 SQL 中自动加双引号 |
| 系统视图 `sys_catalog.sys_user` 与用户表同名 | 查询用户表时访问到系统视图 | 配置 `database.schema` 后所有表名都带 schema 前缀 |

#### 注意事项

- 金仓库开启 `enable_ci` 时字符串比较不区分大小写（如用户名 `Admin` 与 `admin` 视为相同）。这是建库时确定的，不影响本系统使用。
- 绕过服务端直接用 `ksql` 等工具向业务表写数据时，如果涉及空串，先执行 `SET ora_input_emptystr_isnull = off;`；查询时表名要带 schema（`xiaoxin.sys_user`）。
- **重新初始化（清空本系统全部数据）**：停止服务后，用 `ksql` 或其他客户端以业务用户执行 `DROP SCHEMA xiaoxin CASCADE;`，再执行第 4 步。只删除本系统的 schema，不要删库，库里可能还有其他业务的数据。执行前先做备份（见 8.3）。
- 需要在同一个库里并存多套环境（如测试用）时，给每套环境配置不同的 `database.schema` 即可；冒烟测试就是用临时 schema `xiaoxin_smoke` 执行、完成后删除的。

## 3. 服务端部署

| 方式 | 适用场景 |
|---|---|
| 3.1 一键部署（推荐） | 服务器能访问 yum 源和 PyPI 镜像 |
| 3.2 内网离线部署 | 服务器无法访问外网，但有内部 yum 源 |
| 3.3 Docker 部署 | 已有容器环境 |
| 3.4 手动部署 | 需要逐步控制每个环节，或数据库由 DBA 管理 |
| 3.5 无 root 权限部署 | 只有普通用户账号；或系统自带 Python 低于 3.8 又不能安装系统软件包（已在 CentOS 7 + 人大金仓上验证） |

部署前将整个 `server/` 目录上传到服务器，例如 `/root/xiaoxin-server`：

```bash
scp -r server root@服务器IP:/root/xiaoxin-server
```

### 3.1 一键部署（推荐）

```bash
cd /root/xiaoxin-server
sudo DB_PASS='请替换为强密码' bash deploy/install_centos_arm.sh
```

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `DB_PASS` | xiaoxin123 | 数据库业务用户密码，**生产环境必须指定**，可含特殊字符（自动 URL 编码） |
| `DB_NAME` / `DB_USER` | xiaoxin | 数据库名、用户名 |
| `DB_HOST` / `DB_PORT` | 127.0.0.1 / 5432 | 改为其他地址时视为独立数据库服务器：脚本不在本机安装 PostgreSQL，需 DBA 事先按 2.1 ~ 2.3 建好库 |
| `DB_EXTERNAL` | 空 | 设为 1 时表示数据库已经就绪（如本机已有的人大金仓），即使 `DB_HOST` 是 127.0.0.1 也不安装 PostgreSQL、不执行建库脚本 |
| `DB_SCHEMA` | 空 | 业务表所在 schema，写入 `database.schema`；**人大金仓必须指定**（如 `xiaoxin`）。为空时保留配置文件中已有的值 |
| `PG_VERSION` | 空 | 指定后从 PostgreSQL 官方源安装该版本（如 `13`、`15`、`16`）；为空时 CentOS 7 安装官方源 13，CentOS 8+ 使用系统自带版本 |
| `PORT` | 8000 | 服务端口 |
| `SEED_DEMO` | 0 | 设为 1 时写入演示数据（仅测试环境） |
| `PIP_INDEX` | 阿里云 PyPI 镜像 | 可改为单位内部镜像 |
| `OFFLINE` | 空 | 设为 1 时使用 `deploy/wheels` 中的离线依赖包 |

示例：

```bash
# 测试环境：带演示数据，端口 8010
sudo DB_PASS='Test#2025' SEED_DEMO=1 PORT=8010 bash deploy/install_centos_arm.sh
# 使用 PostgreSQL 16
sudo DB_PASS='强密码' PG_VERSION=16 bash deploy/install_centos_arm.sh
# 使用独立数据库服务器（DBA 已建好库）
sudo DB_HOST=10.0.0.5 DB_PASS='强密码' bash deploy/install_centos_arm.sh
# 使用已有的人大金仓（库和用户由 DBA 提供，见 2.8）
sudo DB_EXTERNAL=1 DB_HOST=金仓IP DB_PORT=54321 DB_NAME=库名 DB_USER=system DB_PASS='密码' DB_SCHEMA=xiaoxin \
  bash deploy/install_centos_arm.sh
```

脚本依次完成：

1. 检测或安装 Python 3.8+（CentOS 7 通过 SCL 安装 rh-python38，CentOS 8 安装 python39）；
2. 本机数据库时：检测或安装 PostgreSQL（版本低于 10 时中止），以 UTF8 编码初始化数据目录，把本机 TCP 认证改为 md5（原文件备份为 `pg_hba.conf.orig`），执行 `00_create_db.sql` 创建用户和数据库；
3. 复制程序到 `/opt/xiaoxin`（替换 `app/`；**已有的 `config.yaml` 和 `data/` 中的业务文件保留**），创建虚拟环境并安装依赖；
4. 写入配置：数据库连接串、`schema`（指定了 `DB_SCHEMA` 时）、`seed_demo`；`secret_key` 仍为默认值时自动替换为随机值；`config.yaml` 权限设为 600；
5. 创建系统用户 `xiaoxin`，执行 `python -m app.init_data` 初始化数据库并输出检查结果；
6. 注册并启动 systemd 服务 `xiaoxin`（依赖实际的 PostgreSQL 服务名），在 firewalld 中放行端口，最后调用 `/api/health` 确认服务就绪。

看到 `{"status":"ok"}` 和“部署完成”表示服务已启动，接着按[第 7 章](#7-部署验证各模块)验证。

> 脚本可以重复执行（例如升级或修复）：已有的数据库、用户、配置文件和业务数据都会保留。**重复执行时会把数据库用户的密码重置为本次的 `DB_PASS`**，并同步写入 `config.yaml`。

### 3.2 内网离线部署

1. 在内网服务器上配置好内部 yum 源（需包含 PostgreSQL 13+ 和 Python 3.8+，或按 2.1 准备好 PostgreSQL 的 rpm）。
2. 在一台能联网的机器上下载 Python 依赖包（参数为服务器的 Python 版本，3.9 填 39）：

```bash
cd server && bash deploy/download_wheels.sh 39
```

> 该脚本下载的是 aarch64（鲲鹏 / 飞腾）的包。x86_64 服务器（海光 / 兆芯）需要把脚本中的 `--platform` 参数改为 `manylinux2014_x86_64`、`manylinux_2_17_x86_64`、`manylinux_2_28_x86_64`。

3. 将整个 `server/` 目录（含 `deploy/wheels`）拷贝到服务器后执行：

```bash
sudo OFFLINE=1 DB_PASS='强密码' bash deploy/install_centos_arm.sh
```

> CentOS 7 离线环境无法访问 PostgreSQL 官方源时，先按 2.1 的“内网离线安装”装好 `postgresql13-server`，脚本会自动识别 `/usr/pgsql-13` 并跳过安装。

### 3.3 Docker 部署

```bash
cd server
# 先修改 docker-compose.yml 中的 POSTGRES_PASSWORD 和 XX_DATABASE_URL 中的密码；生产环境把 config.yaml 中 seed_demo 改为 false
```

### 3.4 手动部署

```bash
# 1. 按第 2 章安装 PostgreSQL、创建数据库和用户（2.1 ~ 2.4）

# 2. 部署程序（只复制需要的数据文件，不要复制开发环境的 data/dev.db、data/uploads）
SRC=/root/xiaoxin-server
sudo mkdir -p /opt/xiaoxin/data/uploads
sudo cp -r $SRC/app $SRC/requirements.txt $SRC/config.yaml /opt/xiaoxin/
sudo cp -r $SRC/data/sample_kb.md $SRC/data/finetune_samples /opt/xiaoxin/data/
cd /opt/xiaoxin
sudo python3.9 -m venv venv              # CentOS 7：sudo /opt/rh/rh-python38/root/usr/bin/python3 -m venv venv
sudo venv/bin/pip install --prefer-binary -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/

# 3. 修改 config.yaml：database.url（人大金仓还要填 database.schema，见 2.8）、server.secret_key（随机长字符串）、server.seed_demo: false
sudo vi /opt/xiaoxin/config.yaml

# 4. 创建运行用户
sudo useradd -r -s /sbin/nologin -d /opt/xiaoxin xiaoxin
sudo chown -R xiaoxin:xiaoxin /opt/xiaoxin && sudo chmod 600 /opt/xiaoxin/config.yaml

# 5. 初始化数据库（方式 A；或由 DBA 按 2.5 方式 B 执行 SQL 脚本）
sudo -u xiaoxin venv/bin/python -m app.init_data

# 6. 前台试运行，确认能启动后 Ctrl+C 退出
sudo -u xiaoxin venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1

# 7. 注册为系统服务（PG_SVC 为实际的 PostgreSQL 服务名：官方源 postgresql-13，系统自带 postgresql）
PG_SVC=postgresql-13
sed -e "s#__PORT__#8000#" -e "s#postgresql.service#$PG_SVC.service#g" $SRC/deploy/xiaoxin.service \
  | sudo tee /etc/systemd/system/xiaoxin.service
sudo systemctl daemon-reload && sudo systemctl enable --now xiaoxin
sudo firewall-cmd --permanent --add-port=8000/tcp && sudo firewall-cmd --reload
```

> **必须单进程运行（`--workers 1`）**：会话中止标记、知识库检索索引缓存和定时任务都在进程内存中，多进程会导致定时消息重复发送、检索结果不一致。
>
> 数据库是人大金仓时，第 1 步改为按 2.8 准备连接信息，第 7 步的 `sed` 不需要替换 PostgreSQL 服务名（服务文件中的 `postgresql.service` 依赖在没有该服务的机器上会被忽略）。

### 3.5 无 root 权限部署（普通用户目录）

适用于只有普通用户账号的服务器，全部文件装在该用户的主目录下，不需要 sudo。与 3.1 ~ 3.4 的区别：

| 项目 | root 部署（3.1 / 3.4） | 无 root 部署 |
|---|---|---|
| 程序目录 | `/opt/xiaoxin` | `~/xiaoxin`（示例为 `/home/xiaoxin/xiaoxin`） |
| Python | 系统软件包（yum / SCL） | uv 下载的独立 Python 3.11，装在用户目录 |
| 进程管理 | systemd 服务 `xiaoxin` | `ctl.sh`（nohup + PID 文件） |
| 日志 | journald | `~/xiaoxin/logs/server.log` |
| 开机自启 | `systemctl enable` | crontab `@reboot` |
| 数据库 | 可由脚本在本机安装 PostgreSQL | 必须使用已有的数据库（PostgreSQL 或人大金仓） |
| 防火墙 | 脚本自动放行 | 需管理员放行服务端口（firewalld 开启时） |

下面的步骤是在 CentOS 7（x86_64）+ 人大金仓上实际执行过的（环境见 1.6）。

**1. 在开发机打包并上传**（只带程序、部署脚本和示例数据，不带开发库 `data/dev.db`、上传文件和日志）：

```bash
cd server
tar --exclude='__pycache__' --exclude='*.pyc' -czf server.tgz \
    app requirements.txt config.yaml deploy tests data/sample_kb.md data/finetune_samples
scp server.tgz 用户名@服务器IP:~/
```

**2. 安装 uv 和 Python 3.11，创建虚拟环境**（在服务器上以普通用户执行，需要能访问外网）：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh                 # 安装到 ~/.local/bin/uv
mkdir -p ~/xiaoxin && cd ~/xiaoxin && tar -xzf ~/server.tgz && mkdir -p data/uploads
~/.local/bin/uv venv -p 3.11 venv                               # 自动下载独立的 Python 3.11
VIRTUAL_ENV=$PWD/venv ~/.local/bin/uv pip install --only-binary :all: \
    -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
venv/bin/python -c "import fastapi, psycopg2, numpy; print('ok', numpy.__version__)"     # 实际输出：ok 2.2.6
```

> **`--only-binary :all:` 不能省**：CentOS 7 的 glibc 是 2.17，新版 numpy 等没有适用的预编译包，不加这个参数时安装程序会改用源码包并尝试编译（实际表现为进入 numpy 的 meson 构建后失败）。加上后会自动选用有预编译包的版本（实际为 numpy 2.2.6）。
>
> 服务器不能访问外网时，uv 和 Python 无法在线下载，需要由管理员安装 Python 3.8+，再按 3.2 的方式准备离线依赖包，用 `python3 -m venv venv` 和 `venv/bin/pip install --no-index --find-links deploy/wheels -r requirements.txt` 安装。

**3. 修改配置**（数据库为人大金仓时按 2.8 填写 `url` 和 `schema`）：

```bash
cd ~/xiaoxin
vi config.yaml          # database.url、database.schema；server.seed_demo: false
# secret_key 换成随机值
KEY=$(head -c 32 /dev/urandom | od -An -tx1 | tr -d " \n")
sed -i "s#^  secret_key: .*#  secret_key: \"$KEY\"#" config.yaml
chmod 600 config.yaml
```

**4. 初始化数据库**：

```bash
venv/bin/python -m app.init_data          # 输出“表数量：39 / 39”，示例见 2.8
```

**5. 启动服务并设置开机自启**：

```bash
cp deploy/ctl.sh . && chmod +x ctl.sh
./ctl.sh start                            # 输出“启动成功，PID xxxx，端口 8000”；其他端口：PORT=8010 ./ctl.sh start
(crontab -l 2>/dev/null | grep -v xiaoxin/ctl.sh; \
 echo "@reboot sleep 30 && $HOME/xiaoxin/ctl.sh start >/dev/null 2>&1") | crontab -
crontab -l                                # 确认 @reboot 条目已写入
```

`sleep 30` 是为了等数据库先启动。使用非默认端口时，crontab 条目也要带上 `PORT=8010`。

**6. 验证**：

```bash
./ctl.sh status                           # 运行中，PID xxxx，{"status":"ok"}
tail -5 logs/server.log                   # 应有“小信助手服务端已启动，数据库：金仓IP:54321/库名”
PATH=$HOME/xiaoxin/venv/bin:$PATH bash deploy/verify_deploy.sh http://127.0.0.1:8000 admin admin123     # 37 项全部通过
```

再从其他电脑访问 `http://服务器IP:8000/api/health`。打不开时说明防火墙没有放行，需要管理员执行 `firewall-cmd --permanent --add-port=8000/tcp && firewall-cmd --reload`。

`ctl.sh` 的用法：

| 命令 | 作用 |
|---|---|
| `./ctl.sh start` | 后台启动（单进程），等待 `/api/health` 就绪，最长 60 秒；已在运行时直接返回 |
| `./ctl.sh stop` | 停止（先正常结束，15 秒未退出则强制结束） |
| `./ctl.sh restart` | 重启（修改 `config.yaml` 后需要） |
| `./ctl.sh status` | 进程状态和健康检查，未运行时退出码为 1 |
| `./ctl.sh log` | 实时查看 `logs/server.log` |

> 这种方式下服务进程异常退出后**不会自动拉起**（systemd 的 `Restart=always` 才有这个能力），生产环境建议申请 root 权限后改用 systemd，或用监控定期执行 `./ctl.sh status`，失败时执行 `./ctl.sh start`。`logs/server.log` 不会自动轮转，需要定期清理或配置 logrotate。

## 4. 服务端配置说明

配置文件：`/opt/xiaoxin/config.yaml`，修改后执行 `systemctl restart xiaoxin` 生效（无 root 部署：`~/xiaoxin/config.yaml`，`./ctl.sh restart`）。

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `server.port` | 8000 | 仅在直接运行 `python -m app.main` 时参考；systemd 方式以服务文件中的 `--port` 为准 |
| `server.secret_key` | please-change-me-xiaoxin-2025 | Token 签名密钥，**生产环境必须修改**（一键脚本自动生成随机值），修改后所有用户需要重新登录 |
| `server.token_expire_hours` | 24 | 登录有效期（小时） |
| `server.upload_dir` | ./data/uploads | 上传文件目录（相对 `/opt/xiaoxin`） |
| `server.seed_demo` | true（一键脚本写为 false） | 终端表为空时是否写入演示数据，**生产环境设为 false** |
| `database.url` | postgresql+psycopg2://xiaoxin:xiaoxin123@127.0.0.1:5432/xiaoxin | 数据库连接串，密码需 URL 编码；人大金仓同样使用 `postgresql+psycopg2://` 前缀，端口一般为 54321 |
| `database.schema` | 空 | 业务表所在 schema，仅 PostgreSQL / 人大金仓生效。PostgreSQL 留空即可（使用 `public`）；**人大金仓必须填写**（如 `xiaoxin`），初始化时自动创建，见 2.8 |
| `database.pool_size` | 10 | 连接池大小 |
| `llm.default_models` | 5 个模型 | **仅初始化时写入数据库**，之后请在管理端“模型管理”中修改 |
| `llm.route_strategy` | priority | priority / round_robin / weighted / scene，初始化时写入系统设置 |
| `llm.session_timeout_minutes` 等 | 60 / 6 / window | 会话超时、上下文轮数、上下文策略，初始化时写入系统设置 |
| `embedding.provider` | local | local（内置，零依赖）/ api（接入 BGE-M3、m3e 等向量服务） |
| `rag.*` | 500 / 80 / 5 / 0.05 / hybrid | 切分长度、重叠、召回数、阈值、检索模式，也可以在管理端“检索测试与策略”中调整 |
| `ocr.provider` | none | none / tesseract / api |
| `finetune.train_command` | 空 | 为空时模拟训练；配置如 `llamafactory-cli train {config}` 后真实训练 |

环境变量（优先级高于配置文件）：

| 变量 | 作用 |
|---|---|
| `XX_DATABASE_URL` | 覆盖 `database.url` |
| `XX_DB_SCHEMA` | 覆盖 `database.schema` |
| `XX_SECRET_KEY` | 覆盖 `server.secret_key` |
| `XX_LLM_API_KEY` | 写入 DeepSeek 模型的 API Key（仅初始化写入模型时生效） |
| `XX_CONFIG` | 指定配置文件路径 |

systemd 方式设置环境变量：`sudo systemctl edit xiaoxin`，加入：

```ini
[Service]
Environment=XX_SECRET_KEY=随机长字符串
```

## 5. 大模型与可选组件

```bat
:: 修改 dist\XiaoxinAssistant\config.json 中的 server

```

### 6.3 客户端配置

```json
{ "server": "http://服务器IP:8000", "client_key": "", "dept": "办公室", "floating": true }
```

| 字段 | 说明 |
|---|---|
| `server` | 服务端地址（也可用环境变量 `XX_SERVER` 临时覆盖） |
| `client_key` | 管理端“系统设置 → 客户端接入密钥”设置后，客户端以设备身份调用智能问答、知识库、合同审查等接口时必须携带相同的值；服务端未设置时可留空。**注意：当前版本的终端上报、心跳、运行数据接口不校验该密钥** |
| `dept` | 终端所属部门 |
| `floating` | 是否显示悬浮助手 |

- 用户级配置保存在 `~/.xiaoxin/config.json`（Windows：`%APPDATA%\XiaoxinAssistant\config.json`），客户端“设置”页修改的内容写到这里，优先于安装目录中的配置。
- 客户端日志：`~/.xiaoxin/client.log`（Windows：`%APPDATA%\XiaoxinAssistant\client.log`）。
- 采集周期等参数由管理端“客户端软件配置”统一下发，无需在终端上修改。
- 已安装杀毒软件的终端，建议把客户端安装目录加入杀毒软件白名单，详见[信创适配说明](信创适配说明.md)。

### 6.4 批量部署建议

- 通过终端管理平台或软件商店分发 .deb 包，安装后统一用脚本写入 `/opt/xiaoxin/config.json`。
- 后续升级：在管理端“版本管理”中上传新版本并发布，客户端会自动检测升级。

登录管理端后，在“系统管理 → 系统设置”的“修改密码”中修改本人密码；管理员可在“系统管理 → 用户管理”中重置其他用户的密码或禁用账号。**上线前必须修改所有默认账号的密码，并删除或禁用不需要的账号**（初始账号见附录 A.1）。

修改数据库用户密码：

```bash
sudo -u postgres psql -c "ALTER USER xiaoxin WITH PASSWORD '新密码';"
sudo vi /opt/xiaoxin/config.yaml        # 同步修改 database.url 中的密码（URL 编码）
sudo systemctl restart xiaoxin
```

### 8.3 备份与恢复

需要备份的内容：**数据库** + **`/opt/xiaoxin/data` 目录** + **`/opt/xiaoxin/config.yaml`**。

```bash
# 备份（建议加入 crontab 每日凌晨执行，并同步到异地）
mkdir -p /backup && D=$(date +%Y%m%d)
sudo -u postgres pg_dump -Fc xiaoxin > /backup/xiaoxin_db_$D.dump
sudo tar -czf /backup/xiaoxin_data_$D.tar.gz -C /opt/xiaoxin data config.yaml
find /backup -name 'xiaoxin_*' -mtime +30 -delete      # 保留 30 天

# 恢复
sudo systemctl stop xiaoxin
sudo -u postgres psql -c "DROP DATABASE xiaoxin;"
sudo -u postgres psql -c "CREATE DATABASE xiaoxin OWNER xiaoxin ENCODING 'UTF8' TEMPLATE template0;"
sudo -u postgres pg_restore -d xiaoxin --no-owner --role=xiaoxin /backup/xiaoxin_db_20250101.dump
sudo tar -xzf /backup/xiaoxin_data_20250101.tar.gz -C /opt/xiaoxin && sudo chown -R xiaoxin:xiaoxin /opt/xiaoxin
sudo systemctl start xiaoxin
```

> 官方源安装且 `pg_dump` 不在 PATH 中时，使用 `/usr/pgsql-13/bin/pg_dump`、`/usr/pgsql-13/bin/pg_restore`。恢复到其他服务器时，`pg_restore` 的大版本需不低于备份时的版本。

**数据库为人大金仓时**，上面的 `pg_dump` / `pg_restore` 换成金仓自带的 `sys_dump` / `sys_restore`（在金仓安装目录的 `bin` 下），并且只备份本系统的 schema；程序目录按实际位置调整（无 root 部署为 `~/xiaoxin`）：

```bash
# 备份
sys_dump -h 金仓IP -p 54321 -U system -d 库名 -n xiaoxin -Fc -f /backup/xiaoxin_db_$D.dump
tar -czf /backup/xiaoxin_data_$D.tar.gz -C ~/xiaoxin data config.yaml

# 恢复：停止服务 → 删除旧 schema → 还原 → 启动服务
#   ksql 中执行：DROP SCHEMA xiaoxin CASCADE;
sys_restore -h 金仓IP -p 54321 -U system -d 库名 /backup/xiaoxin_db_20250101.dump
```

> 金仓的备份恢复命令**没有在 1.6 的环境中实际执行过**，参数以所用金仓版本的文档为准，或交由 DBA 纳入金仓的统一备份。上线前务必做一次恢复演练。

定期在测试环境做恢复演练，确认备份可用。

### 8.4 版本升级

```bash
# 1. 备份（见 8.3）
# 2. 用新版本部署包重新执行一键脚本（保留 config.yaml 和 data；DB_PASS 填当前数据库密码）

sudo cp -r /opt/xiaoxin/app /opt/xiaoxin/app.bak.$(date +%Y%m%d)
sudo DB_PASS='当前数据库密码' PORT=8000 bash deploy/install_centos_arm.sh
# 3. 执行 7.2 验证脚本
```

手动升级：停止服务 → 替换 `/opt/xiaoxin/app` 和 `requirements.txt` → `venv/bin/pip install -r requirements.txt` → 执行版本附带的数据库变更脚本（如有）→ `sudo -u xiaoxin venv/bin/python -m app.init_data` → 启动服务。

无 root 部署（3.5）的升级：

```bash
cd ~/xiaoxin && ./ctl.sh stop
mv app app.bak.$(date +%Y%m%d)
tar -xzf ~/server.tgz app requirements.txt deploy tests          # 不解压 config.yaml，保留现有配置

```

> 初始化工具和服务启动时的自动建表**只会创建新增的表，不会给已有的表增加或修改字段**。如果新版本修改了已有表的结构，必须执行版本附带的 SQL 变更脚本。判断方法：分别在新旧版本目录中执行 `python -m app.init_data --export-sql 目录`，对比两份 `01_schema.sql`。
>
> 回退：停止服务，用 `app.bak.*` 替换 `app`，必要时恢复数据库备份，再启动服务。

### 8.5 日志与磁盘

- 服务日志由 journald 管理，可在 `/etc/systemd/journald.conf` 中设置 `SystemMaxUse=1G` 限制大小。
- `data/uploads` 会随知识库文档、合同和安装包的上传持续增长，应定期检查磁盘空间。
- 数据库体积：`sudo -u postgres psql -c "SELECT pg_size_pretty(pg_database_size('xiaoxin'));"`；`terminal_load_record`、`llm_call_log`、`kb_chunk` 是增长最快的表。
- 无 root 部署时日志在 `~/xiaoxin/logs/server.log`，不会自动轮转，需要定期清理（清理后 `./ctl.sh restart`）或由管理员配置 logrotate。

## 9. 常见问题排查

### 9.1 问题速查

| 现象 | 可能原因 | 处理方法 |
|---|---|---|
| 初始化或启动时报 `connection refused` / `Is the server running` | PostgreSQL 未启动，或连接串中的地址、端口错误 | `systemctl status postgresql-13`（或 `postgresql`），核对 `database.url` |
| `password authentication failed` | 数据库密码错误，或密码含特殊字符未做 URL 编码 | 按 2.4 用 psql 验证密码；按 2.4 对密码做 URL 编码 |
| `Ident authentication failed` | pg_hba.conf 仍为 ident 认证 | 按 2.2 改为 md5 并重启 PostgreSQL |
| `permission denied for schema public` | 数据库属主不是 `xiaoxin`（PostgreSQL 15+ 常见） | `sudo -u postgres psql -c "ALTER DATABASE xiaoxin OWNER TO xiaoxin;"`，或按 2.7 重建数据库 |
| `permission denied for table xxx` | SQL 脚本是用 postgres 执行的，表属主不对 | 在库中执行 `REASSIGN OWNED BY postgres TO xiaoxin;`（仅当该库中没有其他需要保留属主的对象时），或重建数据库后用 xiaoxin 执行脚本 |
| `02_init_data.sql` 报“数据库中已有用户数据” | 库中已有数据（如服务已启动过或已执行过初始化工具） | 正常，无需再执行；需要全新数据时按 2.7 重新初始化 |
| 新增记录时报 `duplicate key value violates unique constraint "xxx_pkey"` | 手工导入数据后自增序列未同步 | `SELECT setval(pg_get_serial_sequence('表名','id'), (SELECT max(id) FROM 表名));` |
| 中文显示为乱码或报编码错误 | 数据库编码不是 UTF8 | `\l` 查看编码；按 2.3 用 `template0` + `UTF8` 重建数据库 |
| 脚本提示 PostgreSQL 版本低于 10 | CentOS 7 已装有自带的 9.2 | 设置 `PG_VERSION=13` 重新执行脚本，从官方源安装新版本（旧版本数据如需保留，先 `pg_dump` 导出） |
| `pip install` 报找不到 psycopg2-binary 等包 | 无法访问 PyPI 镜像，或 Python 版本 / 架构没有对应的包 | 检查 `PIP_INDEX`；离线环境按 3.2 准备 wheels，注意 Python 版本和 CPU 架构要与服务器一致 |
| 安装依赖时开始编译 numpy（出现 meson、找不到编译器等）并失败 | CentOS 7 的 glibc 为 2.17，新版 numpy 没有适用的预编译包，安装程序改用了源码包 | pip 加 `--prefer-binary`，uv 加 `--only-binary :all:`，自动选用有预编译包的版本，见 3.5 |
| 执行一键脚本提示“请使用 root 执行”，或 `sudo: a password is required` | 当前用户没有 root 权限 | 按 3.5 在普通用户目录下部署 |
| 连接金仓时报 `Could not determine version from string 'KingbaseES V008R006...'` | 服务端程序是不含金仓兼容处理的旧版本 | 升级 `app/` 到当前版本（兼容处理在 `app/db.py`） |
| 金仓上初始化或登录时报 `sys_user` 相关错误（字段不存在、无法写入等） | 没有配置 `database.schema`，访问到了金仓的系统视图 `sys_catalog.sys_user` | 在 `config.yaml` 中填写 `database.schema`（如 `xiaoxin`）后重新执行 `python -m app.init_data` |
| 金仓上建表报 `syntax error at or near "level"` | Oracle 兼容模式下 `level` 是保留字；程序是旧版本，或建表语句是手工执行的 | 升级程序并使用初始化工具建表；手工写 SQL 时给 `level` 加双引号 |
| 金仓上写入报 `null value in column "xxx" violates not-null constraint` | Oracle 兼容模式把空串存成了 NULL；程序是旧版本，或数据是绕过服务端手工写入的 | 升级程序；手工写入前执行 `SET ora_input_emptystr_isnull = off;` |
| 连接金仓报 `server closed the connection unexpectedly` | 地址或端口不对（端口能连通但不是金仓服务），或金仓的访问控制不允许该来源 | 核对金仓 IP 和端口（默认 54321）；请 DBA 检查 `sys_hba.conf` |
| 无 root 部署时服务器重启后服务没有起来 | crontab 的 `@reboot` 条目缺失，或数据库启动比服务慢 | `crontab -l` 检查；手工执行 `./ctl.sh start`；必要时加大条目中的 `sleep` |
| 服务正常但其他电脑打不开页面 | 防火墙未放行 | `firewall-cmd --list-ports`，放行 8000/tcp |
| 示例知识库文档状态为“失败” | `data/sample_kb.md` 缺失或无读取权限 | 确认文件存在且属主为 xiaoxin；在管理端知识库中对该文档点击“重试” |
| 管理端页面空白 | 浏览器版本过旧或缓存 | 使用较新的 Chromium 内核浏览器，Ctrl+F5 强制刷新 |
| 登录提示“未登录或登录已过期” | Token 过期或修改了 `secret_key` | 重新登录 |
| 客户端显示离线 | 服务端地址错误、网络或防火墙不通、接入密钥不一致 | 终端上访问 `http://服务器IP:8000/api/health`；核对 `config.json` 的 `server` 和 `client_key`；查看客户端日志 |
| 问答一直返回“本地兜底”提示 | 未配置大模型 Key，或服务器无法访问模型地址 | 在管理端填写 Key 后执行健康检查；在服务器上 `curl -I https://api.deepseek.com` 测试连通 |
| 知识库文档一直是“处理中”或“失败” | 文件损坏、格式不支持、扫描件未配置 OCR | 查看文档的导入日志，点击“重试”；扫描件需要配置 OCR |
| 上传文件失败 | 磁盘已满或目录无权限 | `df -h`；`chown -R xiaoxin:xiaoxin /opt/xiaoxin/data` |
| 定时消息重复发送 | 启动了多个 worker 或多个服务实例 | 确认只有一个服务实例，且使用 `--workers 1` |
| 微调任务一直是模拟训练 | 未配置 `finetune.train_command` | 在 GPU 服务器上安装 LLaMA-Factory 并配置训练命令 |

### 9.2 CentOS yum 源不可用

CentOS 7 / 8 停止维护后官方镜像已下线，`yum install` 报 `Could not resolve host: mirrorlist.centos.org` 或 `404`。处理方法（任选其一）：

1. **使用单位内部 yum 源（推荐）**：按单位规范替换 `/etc/yum.repos.d/` 下的 repo 文件。
2. **使用 vault 归档源**：

```bash
sudo cp -r /etc/yum.repos.d /etc/yum.repos.d.bak
sudo sed -i -e 's/^mirrorlist=/#mirrorlist=/' \
            -e 's|^#\s*baseurl=http://mirror.centos.org|baseurl=https://vault.centos.org|' /etc/yum.repos.d/CentOS-*.repo
sudo yum clean all && sudo yum makecache
```

执行 `yum makecache` 不报错即可继续部署；仍报 404 时，在浏览器中打开 `https://vault.centos.org/` 找到与本机版本（`cat /etc/redhat-release`）和架构对应的目录，手工修改 repo 文件中的 `baseurl`（aarch64 的 CentOS 7 位于 `altarch/7.9.2009/`）。CentOS 7 使用 SCL 安装 Python 时，`/etc/yum.repos.d/CentOS-SCLo-*.repo` 也需要同样修改。

### 9.3 SELinux

一键部署使用的都是系统默认路径（`/opt/xiaoxin`、`/var/lib/pgsql`）和普通端口，默认的 `enforcing` 模式下可以正常运行，不需要关闭 SELinux。如果把 PostgreSQL 数据目录改到了非默认位置，需要为新目录设置 SELinux 上下文：

```bash
sudo semanage fcontext -a -t postgresql_db_t "/data/pgsql(/.*)?" && sudo restorecon -Rv /data/pgsql
```

排查 SELinux 拦截：`sudo ausearch -m avc -ts recent`。
