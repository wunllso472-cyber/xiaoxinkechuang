# 大模型配置说明（DeepSeek）

系统通过“统一调用接口 + 厂商适配器”接入大模型，所有调用（智能问答、知识问答、槽位抽取、合同 LLM 审查、模型评估、文本摘要工具）都走同一路由，配置一次即全局生效。

## 方式一：管理端配置（推荐，即时生效、无需重启）

1. 登录管理端 → 『模型管理 → 模型接入与配置』
2. 编辑内置的 **DeepSeek-Chat**：
   | 字段 | 取值 |
   |---|---|
   | 厂商适配器 | DeepSeek |
   | API 地址 | `https://api.deepseek.com/v1`（私有化部署填内网地址，如 `http://10.0.0.5:8000/v1`） |
   | API Key | `sk-xxxxxxxx` |
   | 模型标识 | `deepseek-chat`（推理模型用 `deepseek-reasoner`） |
   | temperature / top_p / max_tokens / 超时 | 按需调整 |
   | 扩展参数(JSON) | 透传给接口的其他参数，例如 `{"frequency_penalty": 0, "presence_penalty": 0}` |
   | 优先级 | 数字越小越优先，失败时按顺序自动降级 |
   | 默认 / 启用 | 勾选 |
3. 点击行内『健康检查』验证连通性，『调用测试』查看实际回复。

## 方式二：配置文件 / 环境变量（首次启动写入数据库）

`server/config.yaml`：

```yaml
llm:
  default_models:
    - name: DeepSeek-Chat
      provider: deepseek
      base_url: https://api.deepseek.com/v1
      api_key: "sk-xxxx"
      model: deepseek-chat
      temperature: 0.7
      top_p: 0.95
      max_tokens: 2048
      timeout: 60
      priority: 1
      enabled: true
      is_default: true
  route_strategy: priority      # priority / round_robin / weighted / scene
  session_timeout_minutes: 60
  context_window_rounds: 6
  context_strategy: window      # window / summary
```

或启动时设置环境变量 `XX_LLM_API_KEY=sk-xxxx`（会写入所有 provider=deepseek 的默认模型）。
注意：`default_models` 只在模型表为空（首次启动）时导入，之后以管理端为准。

## 路由与降级

- **priority**：默认模型优先，其余按“优先级”排序；首选失败/超时自动切换下一个，最后由“本地兜底(Mock)”保证有响应。
- **round_robin / weighted / scene**：轮询、按权重随机、按“业务场景”字段（chat,kb,contract,slot,eval,tool,summary）优先匹配。
- **灰度发布**：模型的“灰度%”按用户哈希分流，100 为全量；行内『发布』可设置版本号与灰度比例。
- 未填写 API Key 的 DeepSeek / Qwen 模型会被自动跳过，避免无效等待。
- 客户端问答界面可手动选择模型；不选则按路由策略自动选择。

## 其他模型

| 模型 | provider | base_url 示例 |
|---|---|---|
| 通义千问 | qwen | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 星辰大模型(TeleChat) | telechat | 私有化部署的 OpenAI 兼容地址（适配器会把 system 角色转换为首轮对话） |
| vLLM / Xinference / Ollama 等 | openai | `http://host:port/v1` |

新增厂商：在 `server/app/llm/adapters.py` 继承 `OpenAICompatibleAdapter`（或 `BaseAdapter`）实现 `chat/stream`，并加入 `ADAPTERS` 映射即可。

## 向量模型（知识库）

DeepSeek 不提供 embedding 接口，默认使用内置零依赖的 `local` 哈希向量（可直接使用，效果一般）。生产环境建议部署 BGE-M3 / m3e（如 Xinference、text-embeddings-inference），然后修改 `config.yaml`：

```yaml
embedding:
  provider: api
  base_url: http://127.0.0.1:9997/v1
  api_key: ""
  model: bge-m3
```

修改向量模型后需在知识库中对文档执行“重试”重新向量化。
