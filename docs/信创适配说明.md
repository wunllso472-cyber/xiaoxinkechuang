# 信创终端适配说明

需求：适配 4 种 CPU（海光、兆芯、鲲鹏、飞腾）、2 种操作系统、3 个杀毒软件（360、奇安信、安恒）。

## 技术选型保证跨架构

| 组件 | 选型 | 跨架构说明 |
|---|---|---|
| 服务端 | Python 3.8+ / FastAPI / SQLAlchemy / PostgreSQL 或人大金仓 | 纯 Python 代码；依赖均提供 aarch64 与 x86_64 预编译 wheel；PostgreSQL 在 CentOS ARM 官方源可直接安装 |
| 数据库 | PostgreSQL 10+，或国产数据库人大金仓 KingbaseES V8R6 | 金仓通过 PostgreSQL 协议和 psycopg2 驱动接入，无需专用驱动；版本识别、Oracle 兼容模式的空串与保留字差异由服务端自动处理，表建在独立 schema 下。已在 KingbaseES V008R006C006B0021（Oracle 兼容模式，x86_64）上验证，见部署手册 2.8 |
| 管理端 / H5 | Vue3 + Element Plus / Vant（已内置到 `static/vendor`，无需外网、无需构建） | 浏览器端运行，与 CPU 无关 |
| 桌面客户端 | Python + Tkinter + psutil，通信只用标准库 | 源码与架构无关；按架构分别用 PyInstaller 打包 |

## CPU 适配矩阵

| CPU | 架构 | 服务端 | 客户端打包 | 识别方式 |
|---|---|---|---|---|
| 鲲鹏 920 | aarch64 | ✓（CentOS ARM 主要目标） | 在 aarch64 终端执行 `build_linux.sh` 生成 `xiaoxin_x.y.z_arm64.deb` | `/proc/cpuinfo` CPU implementer `0x48` / lscpu |
| 飞腾 FT-2000/4、D2000 | aarch64 | ✓ | 同上 | implementer `0x70`，Model name 含 Phytium/FT |
| 海光 | x86_64 | ✓ | 在 x86_64 终端执行生成 `amd64.deb` | Vendor ID `HygonGenuine` |
| 兆芯 KX-6000 | x86_64 | ✓ | 同上 | Vendor ID `CentaurHauls`/`Shanghai`，Model 含 ZHAOXIN |

客户端识别出的原始 CPU/OS 名称经管理端『型号数据字典』规范化（如 `Phytium` → `飞腾`，属性“信创”），据此判定是否信创终端；新型号只需在字典中补充，无需改代码。

## 操作系统

- 客户端：Ubuntu、银河麒麟（Kylin V10）、统信 UOS（均为 Debian 系，使用 `.deb` 安装包）；Windows 10/11（PyInstaller 打包 exe）。
- 服务端：CentOS 7/8/Stream（ARM / x86）。CentOS 7 自带 Python 3.6 过旧，安装脚本会通过 SCL 安装 rh-python38。
- Linux 特有功能：APT 清理需 root，客户端通过 `pkexec` 弹出系统授权框；麒麟/统信均自带 polkit。
- 双系统检测：Linux 检查 GRUB 菜单中的 Windows 启动项及 EFI 分区 `Microsoft` 目录；Windows 检查是否存在 Linux 文件系统分区。

## 杀毒软件兼容（360 / 奇安信 / 安恒）

客户端在设计上避免触发主动防御的行为：

1. 不注入进程、不挂钩系统 API、不修改系统启动项（Linux 使用标准 XDG autostart，Windows 使用当前用户 Run 键）。
2. 进程结束只作用于**当前用户**的非关键进程，并经用户二次确认；系统进程和安全软件进程列入保护名单（可在 `procmgr.PROTECTED` 中补充 360/奇安信/安恒进程名）。
3. 垃圾清理仅删除缓存/临时/日志类文件，不触及安全软件目录。
4. PyInstaller 打包程序可能被启发式误报，建议：
   - 对 exe 进行代码签名；
   - 将安装目录 `/opt/xiaoxin`（或 Windows 安装目录）提交给安全软件管理端加入信任白名单；
   - 使用 onedir（默认）而非 onefile 模式，降低误报概率。
